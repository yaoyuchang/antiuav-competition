# 科目3 无人机路径规划 - 接口说明

## 📂 项目结构

```
code/
├── config/                          # 配置文件目录（输入接口）
│   ├── obstacles.csv               # 障碍物配置表格（题面表1）
│   ├── dynamic_motions.csv         # 动态障碍物运动参数与朝向角度
│   ├── start_points.csv            # 起点配置表格
│   ├── goal_points_initial.csv     # 初始终点配置表格
│   └── goal_points_changed.csv     # 3500m切换后终点配置表格
│
├── run_example/                     # 运行脚本
│   ├── run_with_config.py          # 主运行脚本（读取配置）
│   ├── evaluate_metrics.py         # 独立评估脚本（计算指标）
│   ├── config_loader.py            # 配置加载模块
│   └── mamp/                       # 规划器核心代码
│
└── output/                          # 输出目录
    ├── trajectory_output.json      # 轨迹和结果输出
    └── metrics.json                # 性能指标输出
```

## 🔧 接口设计

### 输入接口

#### 1. 障碍物配置 (`config/obstacles.csv`)

| 列名 | 说明 | 示例 |
|------|------|------|
| 编号 | 障碍物编号 (1-19) | 1 |
| 类型 | 1=圆柱, 2=立方体, 3=U型, 4=旋转立方体 | 1 |
| 中心x | X坐标 (北方向, 米) | 300 |
| 中心z | Z坐标 (东方向, 米) | -267 |
| 尺寸1 | 圆柱半径/立方体长度 (米) | 60 |
| 尺寸2 | 立方体宽度 (米) | 0 |
| 高度 | 高度 (米) | 50 |
| 运动信息 | "静态" 或 "运动" | 静态 |

**说明**：
- 类型4（旋转立方体）的障碍物10、11、12为动态障碍物
- 运动参数与朝向角度题面未给出，属于工程假设值，单独放在下面的
  `dynamic_motions.csv` 里（不塞进本表，因为题面表1的列结构是固定的）

#### 1b. 动态障碍物运动参数 (`config/dynamic_motions.csv`)

| 列名 | 说明 | 示例 |
|------|------|------|
| 编号 | 对应 obstacles.csv 里类型为4的障碍物编号 | 10 |
| 运动方向角度 | 往复运动方向与x轴的夹角 (度)，在水平面内 | 30 |
| 振幅 | 往复运动的单侧幅值 (米) | 300 |
| 周期 | 往复运动周期 (秒) | 120 |
| 朝向角度 | 旋转长方体长轴与x轴夹角 (度)，可留空则取默认30度 | 30 |

方向存角度而不是存 xyz 分量，是因为题面图里本来就是"沿30度长轴"这种描述，
存角度可读可改；代码里现算 `[cos θ, 0, sin θ]`，和原先硬编码的写法得到完全
相同的浮点数，不会因为手抄小数位引入精度扰动。

**说明**：
- 这张表是可选的。缺失时代码回退到内置默认值，所以评委只替换题面那张
  `obstacles.csv` 也能正常跑
- 如果新增了类型为4的障碍物，必须在本表里给它一条对应记录，否则会明确报错
  提示缺少配置（而不是默默用错参数）

#### 2. 起点配置 (`config/start_points.csv`)

| 列名 | 说明 | 示例 |
|------|------|------|
| 无人机编号 | UAV编号 (1-24) | 1 |
| X(m) | X坐标 (北方向, 米) | 0 |
| Y(高度) | Y坐标 (高度, 米) | 0 |
| Z(侧向) | Z坐标 (东方向, 米) | -40 |

#### 3. 终点配置 (`config/goal_points_initial.csv`)

格式与起点配置相同。

**新增字段说明**：
- `single_planning_duration_seconds`：官方口径的"单次规划时长"——一次产出全部24条完整路径的墙钟耗时（L1全局引导阶段），不是滚动时域的单周期耗时（`timing_summary_ms`是另一个指标）。
- `total_energy` / `per_uav_energy`：集群总能耗 Σ∫|需用过载|dt，及每架UAV的分项。
- `mean_path_smoothness` / `total_path_smoothness`：路径平滑性 ∫κ²ds。题面未注明是均值还是总和，评分脚本采用**均值**，总和仅供参考。

## 🚀 使用流程

### 步骤1：准备配置文件

将比赛提供的障碍物表格、起点表格、终点表格放入 `config/` 目录：

```bash
cd code
ls config/
# obstacles.csv  start_points.csv  goal_points_initial.csv
```

### 步骤2：运行规划器

```bash
cd run_example

# 基础运行（使用默认配置）
python run_with_config.py --config-dir ../config --mode competition

# 保存输出到指定文件
python run_with_config.py \
  --config-dir ../config \
  --mode competition \
  --cycles 2000 \
  --output output/trajectory_output.json

# 指定随机种子
python run_with_config.py --config-dir ../config --seed 42
```

**运行模式说明**：
- `fixed` - 固定目标点（无干扰）
- `switch` - 3500m目标切换
- `sin` - 正弦扰动目标  
- `random` - 随机噪声目标
- `competition` - 综合模式（切换+正弦+随机，复赛标准）

### 步骤3：计算性能指标

```bash
# 从轨迹输出计算指标
python evaluate_metrics.py --input output/trajectory_output.json

# 保存指标到文件
python evaluate_metrics.py \
  --input output/trajectory_output.json \
  --output output/metrics.json
```

### 步骤4：查看结果

```bash
# 查看指标文件
cat output/metrics.json

# 或使用评估脚本的格式化输出
python evaluate_metrics.py --input output/trajectory_output.json
```

## 📊 评估指标说明

根据比赛要求，计算以下指标；总分按官方权重计算，见下方"官方5项评分指标"。

### 基础指标
- **成功**: 是否完成规划
- **单次规划时长**: 一次产出全部24条完整路径的耗时（秒），官方权重30%
- **任务完成时间**: 从起点到所有UAV到达的时间（秒），官方权重30%
- **到达UAV数量**: 成功到达终点的UAV数量（/24）

### 安全距离指标（官方权重10%）
- **最小UAV间距**: UAV之间的最小距离（要求≥3.0米）
- **最小静态障碍物间距**: UAV与静态障碍物的最小间距（要求≥1.5米）
- **最小动态障碍物间距**: UAV与动态障碍物的最小间距（要求≥1.5米）

### 能耗与平滑性
- **集群总能量消耗**（官方权重20%）: Σ∫|需用过载|dt，24架UAV求和
- **路径平滑性**（官方权重10%）: ∫κ²ds，评分取24架UAV均值

### 碰撞统计
- **UAV碰撞次数**: UAV间距小于3.0米的次数
- **静态障碍物碰撞次数**: 与静态障碍物间距小于1.5米的次数
- **动态障碍物碰撞次数**: 与动态障碍物间距小于1.5米的次数

### 规划性能指标
- **目标更新次数**: 动态目标更新的次数
- **全局引导重规划次数**: A*全局路径重新规划的次数
- **动态排斥次数**: 动态障碍物导致的轨迹调整次数
- **K3求解次数**: 三次多项式求解次数
- **K5求解次数**: 五次多项式激活次数
- **联合搜索次数**: 多UAV协调搜索次数
- **回退次数**: 规划失败回退次数

## 📝 修改说明

与原有代码相比的改动：

1. **修复接口断裂**：`run_with_config.py` 之前调用的 `formal_case()` 不接受CSV路径参数，
   会直接抛 `TypeError`；已合并修复，CSV驱动的起点/终点现在真正能传到规划器里
2. **新增配置加载**：`config_loader.py` 从CSV读取配置
3. **全局变量覆盖**：通过 `load_obstacles_from_config()` 覆盖 `SUBJECT3_OBSTACLE_TABLE`
4. **标准化入口**：`run_with_config.py` 作为面向评委的命令行入口；`animate_phase6b_final_validation.py`
   同步支持 `--config-dir`，两条链路吃同一份CSV输入
5. **独立评估**：`evaluate_metrics.py` 独立计算指标，按官方 30/30/20/10/10 权重给出加权总分
6. **补齐能耗/平滑性**：新增 `mamp/simulation/mission_metrics.py`，从此前被丢弃的细粒度轨迹采样
   （`FinalValidationEvaluator.run()` 里的 `segment_velocities`/`segment_accelerations`）
   积分得到这两项此前无法计算的指标

## ⚠️ 注意事项

1. **动态障碍物运动参数**：题目表格未给出振幅、周期、方向和旋转朝向，这些工程
   假设值现在从 `config/dynamic_motions.csv` 读取（此前硬编码在
   `subject3_environment.py` 里）。该表缺失时回退到内置默认值
2. **坐标系**：代码使用 `[x, y, z] = [North, Up, East]`，与题目 `[X, Y(高度), Z(侧向)]` 一致
3. **Y坐标计算**：障碍物中心Y坐标 = height/2（题目表格未明确给出）
4. **配置文件编码**：请使用UTF-8编码保存CSV文件
5. **平滑性口径**：题面"路径平滑性"未注明是24机均值还是总和，评分默认取均值
   （`mean_path_smoothness`），总和作为 `total_path_smoothness` 一并输出供参考
6. **评分基准是工程假设**：`evaluate_metrics.py` 里 `SCORE_REFERENCES` 定义的各项满分/零分
   阈值题面未给出官方数值，是队内假设（部分参考了架构说明文档里的理论下界），
   不代表比赛真实评分曲线，仅用于本地自查排名趋势
7. **规划时长口径**：`single_planning_duration_seconds` 是"一次产出全部24条完整路径"的
   耗时（约9.6秒量级），和 `timing_summary_ms` 里的滚动时域单周期耗时是两个不同指标，
   不要混用
